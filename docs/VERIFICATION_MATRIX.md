# Verification Matrix

Canonical owner of: **invariant/scenario → test traceability** — which test proves
each reliability invariant and each required scenario, where that test asserts
durable state, and which production code it exercises.

The invariants are [ARCHITECTURE.md](ARCHITECTURE.md) §12, numbered **I1–I18** in
that order. The scenarios are the twelve named in [ROADMAP.md](ROADMAP.md)'s M7
entry, numbered **S1–S12** in that order. What is implemented and verified right
now is [CURRENT_STATE.md](CURRENT_STATE.md).

## How to read this

- **Tests** — the test functions that prove the row, as `` `TestName` (path) ``.
  A row lists several when one is not enough: a contention test and a restart
  test, say, or a store-level test and a real-binary one.
- **Durable-state assertion** — `file:line` at the head this document was written
  against, with what it reads. It is the line where a test reads PostgreSQL
  *after* the operation, by a SQL query or a store read, and asserts on the
  result. An HTTP status, a response body, or in-memory state is not durable
  state, and a test that checks only those does not earn a row.
- **Code path** — the production code the test exercises, as `` `file:Function` ``.
  A `.sql` entry names a schema object the test depends on.
- **Status** — **COVERED**: an existing test, checked in the M7A audit to assert
  durable state. **CLOSED-M7A**: the audit found a gap and M7A added or extended a
  test to close it. **STOPPED**: a gap test exposed a production defect; the row
  points at the failing proof and the invariant is not claimed.

**What the drift check does and does not prove.** `tests/verification` runs under
`make test-unit` and in CI with no infrastructure. It parses this file and checks
that I1–I18 and S1–S12 each appear exactly once in the right table; that every
named test is a real top-level test function in the file named, parsed with
`go/parser` so `//go:build integration` files are read too; that every cited
assertion line lies inside one of that row's own tests; and that every code path
still exists. It does **not** check that a test is load-bearing. A test that
still exists and no longer proves its row passes it. Whether an assertion
bites is settled by mutating the production code it guards and watching it fail,
which is how M7A's new tests were checked (see [CURRENT_STATE.md](CURRENT_STATE.md)).

## Notes on specific rows

- **I3.** The database's refusal of a second active lease is evidenced by the
  partial unique index's definition, read from `pg_indexes`, plus the contested
  claims that end with exactly one `ACTIVE` lease. No test inserts a second
  `ACTIVE` lease and watches PostgreSQL reject it.
- **I15.** Capacity is not a counter. It is the number of `ACTIVE` leases measured
  against a limit, so a literal negative is impossible, and the invariant is
  tested as what it means for any ledger: a release is worth exactly one slot,
  however many times it is reported or repaired. The test exercises the worker's
  limit and the queue's separately, so neither can mask the other.
- **I17 and S11.** A "process" in the scheduler and reconciler restart tests is a
  connection pool, an engine, and the real run loop, started and stopped
  independently, with only PostgreSQL shared. The reconciler is crashed mid-scan:
  a barrier parks its second repair inside its transaction, and the server
  terminates that connection, which is what a process death looks like to
  PostgreSQL. The replacement runs one `RunOnce` pass rather than its timer loop,
  because the loop holds no state between passes. The worker's restart evidence
  is two tests: a real `SIGKILL` of a worker binary (recovered by a different
  worker), and a same-identity replacement boot whose predecessor's lease still
  holds its slot.
- **I18.** The heartbeat, claim, start, renewal, success, failure, and
  cancellation-acknowledgment requests carry no time field. The test offers one
  anyway: in the body, where `api/openapi.yaml` documents an unknown field as a
  `400`, and in headers, which a server accepts and must ignore. In both cases
  every stored timestamp must be PostgreSQL's, bracketed by the database clock
  around the call.
- **S1.** `TestE2E_APIKeyDrivesTheWholeLifecycle` reads the job's status and the
  attempt count from PostgreSQL but not the attempt or lease status, so the first
  test carries the row.
- **S3.** The rejection is layered: lease usability, the status precondition, and
  the `UPDATE` predicates each independently refuse a late report. The test
  therefore pins the error code, which says which layer answered, and compares
  every durable row before and after.
